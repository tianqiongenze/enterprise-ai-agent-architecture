## 1. 系统总体架构（分层）

```mermaid
graph TB
  subgraph UI/入口
    CLI[CLI / python -m dataagent] & API[Agent API / 调度]
  end
  subgraph 应用层
    Comp[DataAgentContainer 组合根]
    WF[Durable Workflow]
    H[Autonomous Harness]
  end
  subgraph 能力底座
    RT[LLM Runtime<br/><控制权/路由/回退/重试>]
    CTX[Context Runtime<br/>装配/预算/契约]
    TL[Tool / Action / Skill]
    MEM[Memory]
    SB[SQL + 云端 Python Sandbox]
    SEC[QueryGateway / Credential Broker / 注入防护]
  end
  subgraph 治理与运营
    EV[EvalOps 三层评测]
    RG[CI Regression Gate / Canary / 回滚]
    TR[Trace / Run Timeline]
  end
  CLI --> Comp
  API --> Comp
  Comp --> WF
  WF --> H
  H --> RT & CTX & TL & MEM & SB
  TL --> SEC & SB
  CTX --> MEM & SEC
  EV --> TR
  RG --> EV
```

## 2. 一次经营诊断的时序（第六/五篇）

```mermaid
sequenceDiagram
  participant U as 用户 <br/>企业运营
  participant R as Durable Workflow
  participant H as Autonomous Harness
  participant RT as LLM Runtime
  participant C as Context Assembler
  participant T as 工具/沙箱
  participant M as Memory
  U->>R: 提交经营问题(GMV 下滑)
  R->>H: 启动 Autonomous Analysis
  H->>C: 组装 Planning Context(指标口径·租户)
  C-->>H: ContextSlice(含硬过滤/预算)
  H->>RT: 调用模型生成分析计划
  RT-->>H: 计划
  loop 分析步骤
    H->>T: query_metric / query_orders
    T-->>H: 结果
    H->>T: python_analyze(沙箱)
    T-->>H: 统计
    H->>M: 检索历史行动/偏好(Recall Contract)
  end
  H->>RT: 生成结论+建议
  R->>R: Verifier + Stop Condition
  R->>R: 高风险动作发起人工审批
  R-->>U: 最终报告 + 审批请求
```

## 3. Run/Checkpoint 状态机（第五篇第3课）

```mermaid
stateDiagram-v2
  [*] --> pending
  pending --> running: 调度
  running --> waiting_approval: 人类审批(高风险副作用)
  running --> succeeded
  running --> failed
  waiting_approval --> running: approved
  waiting_approval --> canceled: rejected
  succeeded --> [*]
  failed --> [*]
  canceled --> [*]
  running --> running: Checkpoint(持久化/可Resume)
  note right of running: 每 Step 结束保存 Checkpoint，\n中断后可 Resume 而非重跑
```

## 5. 控制权矩阵（第五篇第1课：哪些交给模型/代码/人）

```mermaid
quadrantChart
    title 控制权分配（Autonomy vs 风险）
    x-axis 低风险 --> 高风险
    y-axis 全自动 --> 需人工
    quadrant-1 需要人在环
    quadrant-2 模型自主
    quadrant-3 代码确定性
    quadrant-4 系统约束
    "查询指标": [0.3, 0.2]
    "生成分析计划": [0.4, 0.4]
    "SQL 查询网关": [0.2, 0.1]
    "Python 沙箱分析": [0.45, 0.25]
    "创建工单/调预算": [0.8, 0.85]
    "结论生成": [0.5, 0.4]
    "审批决议(人)": [0.85, 0.9]
```

> 说明：横轴=风险，纵轴=自动化程度。落在"需要人在环"象限（工单/调预算）的动作，
> 一律经 `HumanApprovalGate` 审批后执行，并配幂等保护 —— 这正是"有副作用工具的风险分级与 Human Approval"。
