# DataAgent 人工测试操作指南（局域网实测版）

> 适用版本：镜像 `10.100.135.132:5000/dataagent/api:0.2.0`（含 Web 测试控制台 + CRDB 任务查询闭环）
> 部署位置：K8S 集群 `dataagent-prod` 命名空间，4 副本，NodePort **30080**（节点 10.167.2.175 / 10.167.2.176 均可访问）
> 编写日期：2026-09-26 · 所有 URL 与返回示例均为**实测真实值**

## 0. 先回答：有没有前端？

**有，但不是独立的 SPA 前端工程**，而是：

| 入口 | 形态 | 用途 |
|------|------|------|
| **`/console`** | **内置 Web 测试控制台**（本指南主角，浏览器点按钮即可测全部接口） | 人工功能测试 |
| `/graphql` | GraphiQL IDE（官方图形化查询界面） | 交互式 GraphQL 查询 |
| REST API | `POST /v1/analysis` 等 | Postman/curl/程序集成 |
| `/metrics` | Prometheus 文本指标 | 压测/监控观测 |

## 2. 三分钟快速开始（第一条人工测试）

1. 浏览器打开 **`http://10.167.2.175:30080/console`**；
2. 卡片① 点 **`GET /healthz`** → 出现绿色 `HTTP 200 {"status":"alive"...}`；
3. 卡片② 保持默认 query（华东区本月 GMV 下滑原因诊断），点 **同步分析**；
4. 看到绿色 `HTTP 201`，展开 JSON 里有 `run.run_id`（已自动填入卡片③）；
5. 卡片③ 点 **`GET /v1/tasks/{run_id}`** → `HTTP 200 {"status":"succeeded","steps":7,"events":15}`；
6. 卡片④ 点 **执行 Query** → 返回华东/华北等真实 GMV 聚合（来自 CRDB 里 ≥1 亿行 orders 表）。

✅ 走完以上 6 步，你已经完成：健康检查、同步分析、任务查询（落库验证）、GraphQL 大表聚合 四类测试。

## 3. 逐项人工测试用例（TC-01 ~ TC-12）

> 全部用例可直接在 `/console` 完成；"curl 等价命令"见第 4 节。

### TC-01 存活与就绪
- **操作**：控制台① 两个按钮各点一次。
- **预期**：`/healthz` → 200 `{"status":"alive","ts":...}`；`/readyz` → 200 `{"status":"ready","redis":true}`。
- **判定**：两按钮均绿色 200 即通过；`readyz` 若返回 `degraded` 说明缓存不可达（记录并查 §6）。

### TC-02 同步经营分析（主链路）
- **输入**：tenant=ten_a，user=u1，query=`华东区本月 GMV 下滑原因诊断`。
- **操作**：卡片② 点「同步分析」。
- **预期**：HTTP **201**；`run.status="succeeded"`；`run.steps` 共 7 步（autonomous_analysis / plan / query / analyze / conclusion / verifier / budget_adjust）；`events`≥15（Run Timeline 事件流）。
- **判定**：steps 全 succeeded、plan 步有分析计划文本、conclusion 步有结论文本。

### TC-03 异步入队
- **操作**：同输入，点「异步入队」。
- **预期**：HTTP **201**，`{"status":"queued","task_id":"req_..."}`。
- **判定**：返回 queued 即通过。
- **已知边界**：异步消息走内存队列演示模式（集群未部署 Worker 消费者），任务不会落库 —— 状态查询请使用**同步 run_id**（TC-04）。

### TC-04 任务查询（CRDB 落库闭环）
- **操作**：TC-02 完成后，卡片③ 直接点查询（run_id 已自动填入；也可手工粘贴）。
- **预期**：HTTP **200** `{"task_id":"run_xxx","status":"succeeded","steps":7,"events":15}`。
- **判定**：能查到且状态一致 = CRDB 落库闭环通过；随机 ID → **404**（也是正确行为）。

### TC-05 多租户隔离
- **操作**：tenant 分别选 `ten_a` / `ten_b` 各执行一次同步分析。
- **预期**：均 201；两次 `run.steps` 中 query 步的指标结果**不同**（ten_a 含华东/华南订单，ten_b 含华北）。
- **旁证**：控制台④ GraphQL `regionMetrics(tenantId:"ten_1")` 与 `"ten_2"` 返回不同聚合。

### TC-06 幂等防重（409）
- **操作**：卡片② 点「生成」幂等键 → 连点两次「同步分析」。
- **预期**：第一次 **201**；第二次 **409** `duplicate_request`（黄色标签）。
- **判定**：同租户同键第二次必须 409；换 user 或清空幂等键 → 恢复 201。

### TC-07 每租户限流（429）
- **说明**：集群当前配置 `DATAAGENT_GATEWAY_RPS_PER_TENANT=4000 / BURST=8000`，常规手点**不会触发**。验证限流有两种方式：
  - a) 压测触发：在装有 locust 的机器跑 `locust -f tests/load/locustfile.py --host http://10.167.2.175:30080 --headless -u 300 -r 60 --run-time 30s`，观察 429 出现；
  - b) 临时收紧：`kubectl set env deploy/dataagent-api -n dataagent-prod DATAAGENT_GATEWAY_RPS_PER_TENANT=3` 后快速连点（测完改回 4000）。
- **预期**：超阈值请求返回 **429** rate_limited（黄色），其余 201。

### TC-08 GraphQL 大表聚合（≥1 亿行）
- **操作**：控制台④ 直接点「执行 Query」（默认 regionMetrics ten_1 limit 3）。
- **预期**：**200，0.1s 内**返回 3 行真实聚合（读预聚合汇总表 `orders_region_summary`，已不再实时扫 ≥1 亿行）。示例实测：`华东 333614 / 8.43亿`。
- **数据新鲜度**：汇总表由 Job `dataagent-summary-refresh` 刷新（手动触发：`kubectl delete job dataagent-summary-refresh -n dataagent-prod && kubectl apply -f deploy/k8s/dataagent-summary-refresh.yaml`）。
- **变化输入**：改 `tenantId:"ten_2"`、`limit:5` 再执行；`mutation` preset 提交一次异步入队。

### TC-09 GraphiQL 交互式查询
- **操作**：浏览器开 `http://10.167.2.175:30080/graphql`（控制台右上角链接）。
- **预期**：GraphiQL IDE 加载；左侧输入 `{ __typename }` 执行返回 `Query`；可展开 Docs 面板看到 task / memories / regionMetrics / submitAnalysis / saveMemory 全部 schema。
- **进阶**：`{ task(runId:"<TC-02 的 run_id>") { status steps events } }` 应与 TC-04 一致（同一份 CRDB 数据）。

### TC-10 指标端点
- **操作**：开 `http://10.167.2.175:30080/metrics`。
- **预期**：200，Prometheus 文本；`Ctrl+F` 搜 `dataagent_http_requests_total` 可见计数随请求增长。

### TC-11 参数校验（400）
- **操作**：把 query 改成单字符 `x` 再提交。
- **预期**：**400** Validation failed（Pydantic 最小长度 2），控制台显示红色标签。

### TC-12 副作用审批（内核行为验证）
- **操作**：观察 TC-02 返回 JSON 的 steps 里最后一步 `budget_adjust`。
- **预期**：`status:"succeeded"`、输出含 `approved:true` 与 request_id —— 高风险动作经 Human Approval Gate 的证据链（内核离线演示为自动批准）。

## 4. curl / Postman 等价操作

### 4.1 ⚠️ Windows 中文编码坑（必读）
Git Bash / PowerShell 里 `curl -d '{"query":"中文"}'` 会把中文按本地编码（GBK）发送，服务端 UTF-8 解码失败 → **500**（本项目实测踩过）。正确姿势二选一：
```bash
# 方式A：UTF-8 文件体（推荐）
printf '{"query":"华东区本月 GMV 下滑原因诊断","tenant_id":"ten_a","user_id":"u1"}' > body.json
curl -s -X POST http://10.167.2.175:30080/v1/analysis \
  -H "Content-Type: application/json" --data-binary @body.json
# 方式B：纯 ASCII query
curl -s -X POST http://10.167.2.175:30080/v1/analysis \
  -H "Content-Type: application/json" -d '{"query":"GMV decline","tenant_id":"ten_a"}'
```
（或直接用 `/console`——浏览器 fetch 天然 UTF-8，无此问题。）

### 4.2 Postman 要点
- Method `POST`，URL `http://10.167.2.175:30080/v1/analysis`，Body → raw → **JSON**（Postman 默认 UTF-8，无编码坑）；
- 集合变量：`base = http://10.167.2.175:30080`；建议把 §3 的 12 个用例按顺序串成 Collection，并在 Tests 里断言 `pm.response.code`。

## 6. 故障排查表

| 症状 | 可能原因 | 处置 |
|------|----------|------|
| 浏览器打不开 30080 | 不在同网段 / 防火墙 | `ping 10.167.2.175`；换另一节点 IP；跨网段走 §7 隧道 |
| 页面 404 | 镜像版本旧（无 console） | 确认镜像 digest `1d0b47f...`；`kubectl rollout restart` |
| 分析接口 500 且 query 含中文 | curl 本地编码（§4.1） | 用 `--data-binary @file` 或改用控制台 |
| 任务查询 404 | 用了异步 task_id（不落库） | 改用**同步** run_id |
| GraphQL 返回空数组 | 该租户在汇总表无数据 | 用 `ten_1`/`ten_2`；必要时刷新汇总表 Job |
| GraphQL 报 "No license installed…concurrently open transactions" | **共享 CockroachDB 免费许可的集群级并发事务上限(≤10)被其他负载占满**（2026-09-26 实测发生过） | 已修复：regionMetrics 走预聚合汇总表+Redis 镜像（毫秒级短事务，几乎不再触碰闸门）；若仍偶发，等几秒重试或重跑刷新 Job。任务查询自动回退 Redis 镜像 |
| 大量 429 | 触发每租户限流 | 按 TC-07 调整阈值 |
| Pod CrashLoop | 拉不到镜像 | `kubectl describe pod` 看 Events；确认 imagePullPolicy: Always |

## 8. 边界状态（第三轮已闭合三项 + 剩余说明）

1. ✅ **异步任务真实落库**（已闭合）：`async_=true` 经 Pulsar 优先/Redis 兜底队列 → `dataagent-worker` 消费 → CRDB `dataagent_tasks/runs` 落库 → 任务查询可查 `queued→running→waiting_approval→succeeded/canceled` 全生命周期；
2. ✅ **JWT 鉴权 + RBAC**（已闭合）：所有业务/管理路由需 `Authorization: Bearer <JWT>`；登录 `POST /login`（admin/admin123 · approver/approve123 · analyst/analyst123）；RBAC 四角色，越权 403；
3. ✅ **真实审批人接入**（已闭合）：manual 审批模式下 `budget_adjust` 在 human_gate 中断（waiting_approval）→ 审批中心批准/拒绝（含完整动作上下文与 decided_by 审计）→ 后台自动恢复 → succeeded/canceled；
4. ℹ️ **LLM 内核为离线引擎**：结论由可编程内核生成（可复现），接真实 LLM 按 `docs/07` §2 切换 LiteLLM/Ollama；
5. ℹ️ **发布与灰度/Kill Switch**：控制台操作（state 落 CRDB+Redis），对接真实网关分流为下一迭代。
