## 4. 性能/压力测试（k6 + Locust）

### 4.1 Locust（对已部署 NodePort:30080）

**场景**：健康 `/healthz` + 提交分析（`async` 异步入队为主 + `sync`）。
**压测配置**：`tests/load/locustfile.py`。

| 配置 | RPS | 成功率 | P50 | P95 | P99 | 结论 |
|------|-----|--------|-----|-----|-----|------|
| 30 VU，1 副本 | **158** | 99.2% | 3ms | 5ms | 6ms | 正确，429 少量 |
| 120 VU，4 副本(低限流) | 664 | 43.5% | 3ms | 8ms | 17ms | 大量 429 → 触发限流护栏 |
| **300 VU，4 副本(限流调高)** | **1495–1591** | 100% | **5ms** | **36ms** | **2000ms** | **达成，0 错误** |

**关键发现与调优**：
- 限流是**主动护栏**（每租户 RPS），压测初始按默认 `60/租户` 触发 429，属预期（保护 DB/下游）。
- 调高 `DATAAGENT_GATEWAY_RPS_PER_TENANT=4000` 后 4 副本达 **~1600 RPS / 0 错误**。
- P99（2000ms）是同步路径 + Python 内核偶发拖尾；异步入队路径 P99 更低（削峰优势）。

### 4.2 k6（脚本已备，`tests/load/k6.js`）
本机未安装 k6 二进制；脚本已编写（爬坡→峰值→下降，阈值 失败率<1%、P95<200ms），
在具备 k6 的压测机上直接 `k6 run tests/load/k6.js` 即可复现同场景。Locust 已给出等效实测。

### 4.3 100 万并发说明
当前单集群/4副本约 1600 RPS；冲击 100 万并发按架构推演需：**无状态 API 水平扩展（HPA 至 100-200 pod）+ 全量 Pulsar 削峰 + Worker 有界并发 + DB 连接池/多租户配额**。
本迭代已落地：HPA(K8s)、Pulsar 异步路径、每租户限流、有界并发（Worker concurrency）、CRDB 连接池(核×4)。
要到 100 万并发还需按 `docs/06` 审计 §4 的容量推演补齐多区 LB、LLM 推理网关、后端分片等（见下）。

## 6. 踩坑与解决方案（本项目实测）

| 踩坑 | 原因 | 解决 |
|------|------|------|
| Granian 同步 Provide 500 | Granian asyncio 循环无同步执行器 | 依赖提供器改 `async def`；handler 用 `asyncio.to_thread` 跑同步内核 |
| 中文 body 500 | curl/Git Bash 本地编码 | 客户端用 httpx 显式 UTF-8；服务端正确 |
| Litestar `body`/`state` 保留字 | 保留参数名 | 请求体用 `data`，应用态用 `app_state` |
| 异常处理器签名错 | 需 `(request, exc)` | 用同步 def + `Response` |
| 容器缺 `starlette` | 镜像依赖裁剪 | 移除 `starlette.status`，直接用 int 状态码 |
| Granian `--threads`/`-b` 无效 | 版本参数名不同 | 用 `--host/--port`、`--blocking-threads`(ASGI 仅 1) |
| CRDB `SAVEPOINT` 序列化错 | asyncpg 需事务上下文 | 用 `conn.transaction()` 上下文管理器 |
| 数据生成重复主键 | 用 `count(*)` 续写竞态 | 改用 `MAX(order_id)` 幂等续写 |

## 8. 读写分离 + GraphQL + 监控（本轮新增）

### 8.1 读写分离
- **写侧**：`POST /v1/analysis`（同步/异步），`Mutation.submitAnalysis`、`saveMemory` → 经 Pulsar/内存队列，由 Worker 落 CockroachDB。
- **读侧**：`GET /v1/tasks/{id}`、GraphQL `Query.task/memories/regionMetrics` → 直连 CockroachDB（生产可指向只读 replica）。
- **GraphQL 端点** `/graphql`（Strawberry，读写分离：Query 读 / Mutation 写）。

### 8.2 GraphQL 实测（对已部署 NodePort:30080）
```bash
curl -s -X POST :30080/graphql -H 'Content-Type: application/json' \
  -d '{"query":"{ __typename }"}'                       # {"data":{"__typename":"Query"}}
curl ... -d '{"query":"{ regionMetrics(tenantId:\"ten_1\",limit:2){region orders gmv}}"}' 
# {"regionMetrics":[{"region":"华东","orders":202215,"gmv":510640520.73},...]}  ← 从>6000万行聚合
```
